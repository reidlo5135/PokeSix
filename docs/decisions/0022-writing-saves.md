# 0022 — 세이브 쓰기: 다른 이름으로만, 다시 읽어 확인한 뒤 (ADR 0018 결정 2 대체)

- 상태: 채택 (2026-10-20)
- 대체: [ADR 0018](0018-save-import-read-only.md)의 결정 2("읽기 전용"). [ADR 0021](0021-editor-page-for-saves.md) 결정 5가
  "새 ADR로 정한다"고 남긴 쓰기 조건을 이 문서가 정한다
- 관련: 로드맵 H10a–H10f · 가이드 [h10-save-editor.md](../guides/h10-save-editor.md)

## 배경

H9에서 에디터는 세이브의 파티를 읽어 보여 주기만 했다. 사용자 결정(2026-10-20):

- 에디터 카드를 **스쿼드 카드 수준으로 완성**한다("sav 버전의 스쿼드 페이지")
- PKHeX처럼 **고쳐서 저장**한다. 4 · 5세대 모두
- core부터 화면까지 **전부 사용자가 구현**한다(학습 루프)

쓰기는 실제 진행 중인 세이브를 망가뜨릴 수 있다(ADR 0018이 읽기 전용을 고른 이유). 그래서 무엇을 어떻게 쓰는지를
먼저 정한다.

## 결정

1. **원본 파일에는 쓰지 않는다.** 저장은 [다른 이름으로 저장]만 있다. 기본 이름은 `<원본 이름>-edited.<원본 확장자>`.
   원본과 같은 경로를 고르면 거부한다
2. **쓰기는 읽기의 역순이고, core(Qt 없음)에서 한다.**
   고친 칸 → 포켓몬 체크섬 → 블록 섞기 → 암호화 → 블록 CRC. 블록 CRC는 검증 방식마다 함수 하나다
   (4세대 `FooterSlots`: 지금 슬롯의 footer CRC · 5세대 `ChecksumTable`: 파티 CRC 두 곳 → 모음 블록 CRC).
   [ADR 0019](0019-save-readers-per-platform.md)의 `findBase`처럼 `std::visit`으로 고른다.
   역연산(`writeU16` · `encodePkm` · CRC 쓰기)을 core에 새로 짠다. `tests/core/syntheticsave.h`의 같은 역연산은
   **독립된 정답지로 남긴다**(2026-10-23 수정 — 정답지가 검사받는 코드와 같으면 둘이 같이 틀려도 테스트가 통과한다)
3. **4세대는 지금 슬롯(`activeGeneralBlock`)만 고친다.** 저장 카운터는 올리지 않는다. 게임은 CRC가 맞고 카운터가
   큰 슬롯을 읽으므로, 카운터를 그대로 두면 고친 슬롯을 계속 읽는다. 다른 슬롯(한 번 전의 저장)은 손대지 않는다
4. **파일로 쓰기 전에 다시 읽어 확인한다.** 만든 바이트를 `readParty`로 다시 읽어 ① 체크섬이 모두 맞고 ② 고친 값이
   그대로 나오고 ③ 고치지 않은 멤버 · 칸이 그대로일 때만 쓴다. 아니면 쓰지 않고 이유를 보인다.
   파일은 `QSaveFile`로 쓴다(다 쓴 뒤 한 번에 바뀐다 — 쓰다 멈춰도 반쪽 파일이 남지 않는다)
5. **고칠 수 있는 값과 그 조건** (단계는 로드맵 H10a–H10f)

   | 값 | 조건 |
   |---|---|
   | 기술 4 | PP는 새 기술의 기본 PP, PP 업은 0. 빈 칸(0)도 고를 수 있지만 첫 칸은 비울 수 없다 |
   | 지닌 물건 | 그 세대에 있는 것만. 앱의 아이템 id → 게임 번호(H2 변환의 역) |
   | 레벨 | 경험치를 그 레벨의 최솟값으로 함께 바꾼다(성장 곡선 데이터를 새로 받는다 — 스키마 올림). 실능력치를 공식으로 다시 계산 |
   | 개체값 · 노력치 | 개체값 0–31, 노력치 하나 0–255 · 합 510 이하. 실능력치를 다시 계산 |
   | 성격 | **5세대만**(0x41 바이트). 4세대 성격은 PID에서 나와서 PID를 바꿔야 하는데, PID는 색이 다른 개체 여부 · 성별 · 블록 섞기까지 바꾸므로 하지 않는다 |
   | 특성 | 그 종의 일반 특성(칸 1 · 2) 중에서. 숨겨진 특성 표시(5세대 0x42)는 건드리지 않는다 |
   | 별명 | **5세대만**(UTF-16). 4세대는 전용 글자표가 필요하고, 공개된 표(PKHeX)는 GPL이라 옮기지 않는다 |

   종 바꾸기 · 알 고치기 · 새 포켓몬 넣기 · 박스는 하지 않는다(PID · 특성 · 폼이 얽힌다)
6. **합법성 검사(PKHeX Legality 같은 것)는 하지 않는다.** 고친 칸에 "게임 안에서는 나올 수 없는 조합일 수 있어요" 정도만 보인다
7. **화면 설계(배치 · 카드 모양 · 편집 방식)는 사용자가 정한다.** ADR 0021 결정 6과 같다

## 결과

- 원본은 늘 남는다. 망가진 세이브가 생겨도 원본으로 돌아갈 수 있다
- 쓰기 코드가 core에 생겨, 합성 세이브 테스트가 "읽기 → 쓰기 → 다시 읽기" 왕복으로 쓰기를 검증한다
- 성장 곡선(경험치 표)을 받으려고 스키마 버전이 오른다(H10e). 기존 사용자는 첫 실행 때 다시 받는다
- 4세대 성격 · 별명은 이번 범위에서 빠진다. 필요해지면 새 ADR로 정한다
