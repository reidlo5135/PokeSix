# 0021 — 세이브(.sav)는 새 [에디터] 페이지에서 받는다 (ADR 0018 결정 1 대체)

- 상태: 채택 (2026-10-19)
- 대체: [ADR 0018](0018-save-import-read-only.md)의 결정 1("새 화면을 만들지 않는다"). 결정 2(읽기 전용)는 H10에서 다시 정한다
- 관련: 로드맵 H9 · H10 · 가이드 [h9-editor-page.md](../guides/h9-editor-page.md)

## 배경

ADR 0018은 `.sav`를 "파티 6마리가 든 또 하나의 스쿼드 파일"로 보고 스쿼드 페이지의 불러오기에 더했다.
써 보니(사용자, 2026-10-19) 두 성격이 섞였다:

- **구상**(`.pks`): 정주행 전에 짜 보는 파티. 손으로 고치고 저장한다
- **현황**(`.sav`): 지금 게임 속 실제 파티. 레벨 · 인게임 능력치가 붙어 있다

같은 세대 · 게임에서 둘을 오가면 불러올 때마다 서로를 덮어써서, 구상하던 스쿼드가 사라지거나
현황이 구상과 섞였다. 사용자는 PKHeX처럼 세이브를 따로 다루는 화면을 원했다.

## 결정

1. **앱 막대에 [에디터] 탭을 새로 둔다.** `.sav` · `.dsv`는 에디터에서만 받는다(끌어다 놓기 · 열기 대화상자).
   스쿼드 페이지는 `.pks` · `.json`만 받는다
2. **에디터는 세이브의 파티를 그대로 보여 준다.** 불러와도 스쿼드 저장소(`SquadStore`)를 건드리지 않는다
3. **스쿼드로 옮기는 건 사용자가 고를 때만**("스쿼드로 보내기"). 그때는 지금의 불러오기와 같은 흐름이다 —
   덮어쓰기 확인 → 세대 · 게임 전환 → `replaceSquad`
4. **페이지끼리는 서로를 모른다.** 에디터는 "보내 달라"는 시그널만 내고, `MainWindow`가 스쿼드 페이지에 잇는다
   (인트로 · 앱 막대가 페이지를 여는 방식과 같다)
5. **H9는 읽기만 한다.** 세이브에 쓰는 편집(H10)은 범위를 따로 정한다. ADR 0018 결정 2의 위험(진행 중인 실제
   세이브를 망가뜨림)은 그대로라, 열 때는 백업 · 체크섬 다시 계산 · 쓰기 전 확인을 새 ADR로 정한다
6. **화면 설계(배치 · 카드 모양 · 빈 상태)는 사용자가 정한다.** 핸드오프에 없는 화면이다

## 결과

- 구상과 현황이 분리된다. 스쿼드 페이지의 동작(불러오기 · 끌어다 놓기)은 `.sav`가 빠지는 것 말고는 같다
- 파서(`core/save`) · 변환(`data/store/saveimport`)은 그대로 쓴다. 바뀌는 건 ui 레이어(새 페이지 · 탭 등록 · 스쿼드의 받는 형식)뿐이다
- 탭이 6개가 된다. 앱 막대 폭과 Ctrl+숫자 단축키를 함께 손본다
