# 디자인 요청 0002 — 다크 테마 완성 · 앱 막대 7탭 (웹 재작성)

> Claude Design에 그대로 붙여 넣는 요청서다. 기존 핸드오프(`design/handoff-v1/` + `design/handoff-v2/`)의 디자인 시스템을 **그대로 이어서** 쓴다.
> 결과물은 기존 핸드오프와 같은 구성으로 받아 `design/handoff-v3/`에 둔다. 기존 폴더는 수정하지 않는다.

---

## 0. 배경

PokeSix는 포켓몬 시리즈를 세대별로 정주행하는 성인 플레이어용 도구다. 지금까지 C++ / Qt 6 Widgets로 만들었고(v0.1–v0.5),
이번에 **웹 기술(React · TypeScript)로 처음부터 다시 만든다.** 같은 코드가 세 곳에서 돈다:

- **데스크톱(Electron) — 메인 플랫폼.** 1440×900 기준, 최소 창 960×640
- 웹 브라우저
- 모바일(Capacitor) — 나중 단계. 이번 요청에는 참고 1장만

**유지하는 것**: v1 · v2의 색 토큰과 이름, 타입 18색, 타이포그래피(제목 도현 · 본문 나눔고딕 · 숫자 나눔고딕코딩 · 워드마크 Silkscreen),
먹색 2px 외곽선, 블러 없는 오프셋 그림자, 컬러 머리의 각진 창, 노란 선택 칸 + ▶ 커서, 캡슐 마크, 해요체 문구, 대비 4.5:1,
키보드 조작, **포켓몬 공식 에셋 · 포켓볼 도안을 쓰지 않는다는 원칙**.

**화면은 v1 핸드오프 그대로 구현한다**(사용자 결정 2026-10-26): v1의 엔트리 홈(SCR-01 — 세대 카드 9장 · 최근 스쿼드 · 바로 가기),
도감(SCR-02 — 필터 · 목록 · 상세 3단), 아이템(SCR-03 — 분류 · 목록(세대 1–9 칸) · 상세 3단), 스쿼드(SCR-04), 설정(SCR-05).
v2의 인트로(타이틀) 화면은 **쓰지 않는다**. 마크는 v2의 **캡슐**을 쓴다(v1 홈 이미지의 육각 마크는 캡슐로 읽는다).

이번 요청은 두 가지다: **① 다크 테마를 끝까지 채우기 ② 페이지가 7개로 는 앱 막대.**

## 1. 다크 테마 완성

### 문제

`tokens.json`의 `color.darkOverrides`에는 11색만 있다(paper · white · paper.alt · raised · red · ink · text.1–3 · line · line.soft).
나머지 **43색은 다크 값이 없어서 라이트 값이 그대로 쓰인다.** Qt판에서 실제로 생긴 문제:

- 사선 무늬(`intro.stripe` · `paper.stripe`)가 다크 바탕(`#1B1B21`) 위에서 **검정 · 크림의 강한 줄무늬**가 됐다(빈 슬롯 무늬도 같은 위험)
- 연한 틴트(`red.tint` · `blue.tint` · `yellow.tint` · `green.tint` · `yellow.rowSel` · `blue.cell`)가 다크 화면에서 **밝은 형광 띠**처럼 떴다
- 세대 버튼의 파스텔 바탕 위 글자가 안 읽혔다

### 요청

1. 다크 값이 없는 43색 각각에 **다크 값** 또는 **"그대로(이유)"** 를 정해 달라
   - 기존 규칙 "타입 색과 히트맵 색은 그대로 두고 바탕 · 선 · 글자만 교체"는 유지하되, 그대로 둔 색 위의 **글자 대비**는 다크 바탕 기준으로 다시 확인
   - 틴트 계열은 "다크 바탕 위의 같은 의미"(예: 문제 행 = 어두운 붉은 기)가 되게
2. 상태 색(hover · 키보드 선택 · 눌림 · 포커스 링 · 비활성)이 다크에서 어떻게 보이는지
3. 대비표: 글자색 × 바탕색 조합마다 대비 수치(4.5:1 미만은 표시)

다크 대상 43색: `red.deep` `red.tint` `red.text` `paper.stripe` `blue` `blue.deep` `blue.tint` `blue.cell` `blue.focusRing` `green` `green.tint`
`yellow` `yellow.tint` `yellow.soft` `yellow.rowSel` `text.disabled` `line.strong` `cell.border` `stat.low` `stat.mid` `stat.good` `stat.high`
`cat.physical` `cat.special` `cat.status` `heat.x4` `heat.x2` `heat.x2.text` `heat.half` `heat.half.text` `heat.quarter` `heat.zero`
`capsule.*`(4) `plate.*`(4) `intro.stripe` `intro.titleShadow` `menu.pressed` — 아이콘 전용(`plate.*` · `capsule.*`)은 "그대로"여도 된다

### 받을 것

- `tokens.json`: `darkOverrides`를 채운 갱신본(키 이름은 그대로)
- 다크 견본 보드: 기초(색 · 타입 칩 · 글꼴 — v1 `00_foundations` 다크판), 컴포넌트(버튼 · 창 · 칩 · 입력 · 표 행 상태)
- 대비표

## 2. 앱 막대 7탭 — v1 SCR-00 수정

v1 앱 막대는 탭 5개(홈 · 도감 · 아이템 · 스쿼드 · 설정)다. Qt판을 만들며 페이지가 둘 늘었다:

- **에디터** — 게임 세이브(.sav)의 파티를 보고 고치는 화면(PKHeX 같은 도구의 간단판)
- **타운맵** — 지방 지도 위에서 장소별 출현 포켓몬을 보는 화면

### 요청

- 탭 7개: **홈 · 도감 · 아이템 · 스쿼드 · 에디터 · 타운맵 · 설정**(이 순서) — 탭 아이콘 둘(에디터 · 타운맵) 추가, 기존 아이콘과 같은 선 굵기 · 크기
- 오른쪽은 v1 그대로 **세대 버튼(`GEN n` 뱃지 + 지방 이름 ▾) · 전체 검색**. 여기에 **테마 스위치(라이트 · 다크 · 시스템)** 를 넣을 자리도 정해 달라
- 왼쪽 마크는 v2 캡슐(빨강 바탕용 변형)
- 1440 · 1024 · 960 폭에서 7탭이 넘치지 않게 — 좁아지면 어떤 탭부터 아이콘만 남기는지(v1은 1024 이하에서 설정만 아이콘)
- 홈 화면에서도 앱 막대는 같다(v1처럼). 홈의 세대 카드로 고른 세대가 세대 버튼에 그대로 보인다
- 활성 · 비활성 · hover · 포커스 상태, 라이트 · 다크 각각

### 나중에 따로 요청할 것 (이번엔 아님)

에디터 · 타운맵 **본문 화면**은 v1에 없다. 그 페이지를 만들 때 따로 요청한다. 이번에는 탭만.

## 3. 결과물 형식 (웹 기준)

기존 핸드오프와 같은 구성으로 받되, **웹 구현에 맞게** 몇 가지를 바꾼다.

- `images/screens/`: v1의 화면들(홈 · 도감 · 아이템 · 스쿼드 · 설정) **다크판** 1440 각 1장 · 7탭 앱 막대(1440 · 1024 · 960, 라이트 · 다크, 상태) · 다크 기초 보드
- `design/source/*.dc.html`: 수치의 정답. **레이아웃은 가능하면 flex / grid로**(예: "메뉴 = 세로 flex, gap = space 12, 폭 520 고정") — 좌표 배치보다 웹으로 옮기기 쉽다
- `design/tokens.json`: 1절 다크 값 + 7탭에 새로 필요한 토큰(있다면). **키 이름 규칙은 그대로**(`red.deep` 등) — 코드에서는 이 이름이 `--color-red-deep` 같은 CSS 변수가 된다
- `docs/`: 바뀐 부분만 — 다크 표 · 대비표, SCR-00(7탭)
- **받지 않는 것**: React 컴포넌트 코드(구현은 사람이 직접 한다) · Qt용 `Tokens.h` · `pokesix.qss` 갱신
